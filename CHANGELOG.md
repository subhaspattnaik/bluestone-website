Moved that 851px cap onto just the heading/paragraph elements (`.market-stats__title/__body/__pull`) and left `.market-stats__copy` itself unconstrained, so the KPI row can use the full width of its actual grid column (up to 72% of the section) on large screens without changing the heading/paragraph width.

Total: ~17.5MB → ~1.3MB, no visible quality loss at any size the images are actually displayed.

### Fixed
- (2026-07-31) `EcosystemFlow`'s connector arrows pointed right (→) even when the row stacked into a single column on narrow screens (≤680px), reading as disconnected/wrong. Rows now stack vertically below 680px with arrows rotated to point down. Actually applying the rotation required wrapping each arrow icon in a non-animated `<span>`: the icons are direct children of a `.reveal-stagger` container, and `scrollAnimations.js` sets an inline `transform: translateY()` on every direct child when it animates in — that inline style was silently overriding the CSS `rotate(90deg)` regardless of specificity, since inline styles always win. The wrapper span now absorbs the scroll-reveal transform, leaving the icon's own CSS transform free.
- (2026-07-31) On mobile, `TractionMetrics`' partner-logos column rendered with ~90px of dead vertical space between each row. Root cause: `.traction__logos-col`/`.traction__metrics-col` use `flex: 1 1 480px`/`560px` to size themselves as columns in the desktop side-by-side flex layout — but the ≤900px media query switches `.traction__body` to `flex-direction: column`, which flips the flex main axis from horizontal to vertical. The same `480px`/`560px` basis then became a forced *height* instead of a width, pinning the logos column to 480px tall regardless of its (much shorter) actual content. Fixed by resetting `flex-basis: auto` for both columns in that media query. `Intro.jsx`'s `.intro__title` had the identical bug (`flex: 0 0 378px` becoming a 378px-tall forced box once `.intro__inner` stacks to column ≤900px) — same fix applied there.
- (2026-07-31) The four large pill CTA buttons (Hero, CtaBanner, PhotoCta, Contact form submit) used a fixed `padding: 17px 80px`, which could crowd/overflow their text on narrow phones since `.btn` is `white-space: nowrap`.
